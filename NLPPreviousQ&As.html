Q5 — Dependency Parsing: Concept, Types and Algorithms

Question: Explain the concept of dependency parsing and its role in syntactic analysis. Discuss the different types of dependency parsing algorithms with examples.
✅ Answer

Dependency parsing finds grammatical relationships between words. Each word (except root) depends on exactly one head word. The relationship is shown as a labeled directed arc.

Example: "She eats rice"
eats → She  (nsubj: she is subject of eats)
eats → rice (dobj:  rice is direct object of eats)

Types of Dependency Relations

Label Meaning
nsubj Nominal subject
dobj Direct object
det Determiner
amod Adjectival modifier
prep Prepositional modifier

1. Transition-based Parsing (Arc-standard / Arc-eager)

  • Uses a Stack and a Buffer (input queue)
  • Three operations: SHIFT, LEFTARC, RIGHTARC
  • Time complexity: O(n) — fast but greedy (may make early errors)

Example: "She saw him"

Step Stack Buffer Action Arc
0 [ROOT] [She, saw, him] SHIFT —
1 [ROOT, She] [saw, him] SHIFT —
2 [ROOT, She, saw] [him] LEFTARC saw ← She (nsubj)
3 [ROOT, saw] [him] SHIFT —
4 [ROOT, saw, him] [] RIGHTARC saw → him (dobj)
5 [ROOT, saw] [] RIGHTARC ROOT → saw

2. Graph-based Parsing (MST Parser)

  • Builds complete graph with all possible arcs and their scores
  • Finds Maximum Spanning Tree using Chu-Liu/Edmonds algorithm
  • Time complexity: O(n²) — slower but more accurate globally

3. CYK-based Parsing

  • Uses dynamic programming bottom-up
  • Based on PCFG converted to dependency rules
  • Fills a table and backtracks for best parse

✅ Answer — Part (a)
  • TF(t,d) = Count of t in d ÷ Total words in d. Higher = word more frequent in that document.
  • IDF(t) = log(Total docs ÷ Number of docs containing t). High IDF = rare across documents = more informative. Common words like "the", "is" get very low IDF.
  • TF-IDF(t,d) = TF(t,d) × IDF(t). Words frequent in one doc but rare elsewhere get high score. Filters out stop words automatically.

Q2 — FST: Mathematical Representation + Handling Ambiguity

✅ Answer

Mathematical Representation of FST (7-tuple)

FST = (Q, Σ, Δ, δ, λ, q0, F)

Q = finite set of states
Σ = input alphabet
Δ = output alphabet
δ: Q × Σ → Q = transition function (state + input → next state)
λ: Q × Σ → Δ* = output function (state + input → output string)
q0 = start state
F = set of accepting/final states

How FSTs Handle Ambiguity

FSTs are non-deterministic — from a single state, multiple transitions may be possible for the same input. One input string can produce multiple output strings, representing different interpretations.

Example — Morphological Ambiguity with "flies"

Input: "flies"
Path 1: flies → fly/Noun/Plural     (insects)
Path 2: flies → fly/Verb/3rdPersonSingular

[q0] --f--> [q1] --l--> [q2] --i--> [q3] --e--> [q4] --s--> [q5: fly+Verb+3Sg]
                                                         --s--> [q6: fly+Noun+Pl]
💡 ResolutionBoth outputs are valid — FST returns both, and a higher-level language model resolves which is correct based on context.

Q6 — Two Methods to Compute Semantic Similarity

✅ Answer

Method 1: WordNet-based Similarity (Knowledge-based)

Uses the WordNet hierarchy. Wu-Palmer Similarity:

sim(c1, c2) = 2 × depth(LCA) / (depth(c1) + depth(c2))

Example: dog and cat → both under "animal" in WordNet.
depth(dog)=8, depth(cat)=7, depth(animal/LCA)=4
sim = 2×4/(8+7) = 8/15 = 0.53

Method 2: Corpus-based Similarity (Word Embeddings)

Train Word2Vec/GloVe, then compute cosine similarity:

cos(A, B) = (A · B) / (|A| × |B|) Example: cos(king, queen) ≈ 0.95 → very similar
WordNet-based
Interpretable, structured, handles hierarchy. Needs WordNet (may not exist for all languages).
Corpus-based
Language-independent, data-driven, handles new words. Large diverse corpus gives better coverage.

Q4 — Bigram with/without Laplace: "humpty dumpty sat on kings wall" (10 Marks)

✅ Answer — General Method
  1. Count bigrams from all training sentences (large humpty dumpty corpus)
  2. Compute raw P(w2|w1) = C(w1,w2)/C(w1) — if any bigram has count=0 → zero probability problem
  3. Apply Add-1 Laplace Smoothing: P_smooth(w2|w1) = (C(w1,w2)+1)/(C(w1)+V)
  4. Compute sentence probability = product of all bigram probabilities
  5. Compute Perplexity: PP = P(sentence)^(-1/N)
Without smoothing: If any bigram is unseen → P=0 → PP=∞
With smoothing: All bigrams have non-zero probability → PP is finite. Lower PP = better model fit.
