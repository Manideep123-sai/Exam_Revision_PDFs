Q1. A university publishes an anonymized dataset containing details of student exam scores, age, gender, and department. The dataset is intended for transparency and research purposes but does not include names as below.

Student ID Age Gender Department Final Exam Score
S101 19 Male Computer Science 95
S102 21 Female Mathematics 80
S103 22 Male Computer Science 30
S104 20 Female Physics 60

Explain identity disclosure, attribute disclosure and inference disclosure in the context of data privacy. Identify the possible disclosures present in the given dataset and explain their impact. Also apply appropriate privacy preserving technique to mitigate it.

Answer:

Identity Disclosure: Occurs when a specific individual can be uniquely identified in the released data. In this dataset, if external records show a 22-year-old male in Computer Science, S103 can be identified.

Attribute Disclosure: Sensitive information is revealed even without full identity disclosure. If an attacker knows a record belongs to S101 (19, Male, CS), they learn the exact score (95), disclosing academic performance.

Inference Disclosure: An attacker deduces unknown facts from known data. For example, knowing that all CS males in this age bracket scored >90 allows inference about a new CS male student.

Mitigation: Apply k-anonymity (e.g., generalize Age to 18–25, group Departments to "Science/Arts"). This ensures at least k records share identical QI values, preventing exact identification.

Q6. A banking organization wants to enhance the security of its customers' credit card numbers while processing transactions. Instead of storing raw credit card numbers in databases, the bank decides to implement tokenization to protect sensitive data.

  • Explain how tokenization can be applied in this scenario to ensure security.
  • Differentiate tokenization from encryption and explain which method is more suitable for this use case.
  • What are the potential challenges of implementing tokenization in real-time payment processing systems?

Answer:

Tokenization Application:

  1. Customer enters CC: 4532-1234-5678-9012
  2. Tokenization server generates random token: TKN-9F2A-7K3M-8B1N
  3. Token stored in bank's database; original CC stored in secure vault
  4. For transactions: token sent to payment gateway; vault detokenizes securely
  5. BPO/merchants see only tokens; never handle raw CC numbers

Tokenization vs Encryption:

Feature Tokenization Encryption
Reversibility Only via secure vault With decryption key
Relationship to original No mathematical link Derived via algorithm
Format preservation Yes (same length/charset) No (ciphertext differs)
Key management Vault access control only Complex key rotation/storage
Breach impact Tokens useless without vault Ciphertext decryptable if key stolen

More suitable: Tokenization — because CC numbers must be format-preserving for legacy payment systems, and tokens have zero utility if stolen.

Challenges in Real-Time Systems:

  • Latency: Vault lookup adds milliseconds; critical for sub-second payment approvals
  • High Availability: Vault must be 99.999% uptime; single point of failure risk
  • Scalability: Must handle peak loads (e.g., Black Friday: 10K+ TPS)
  • Consistency: Same CC must always map to same token across distributed systems
  • Compliance: Vault must meet PCI-DSS Level 1; audit trails for all detokenization requests

Non-Perturbative Masking Definition: Methods that reduce detail without adding noise or altering actual values — via generalization, suppression, or restructuring.

Sample Dataset:

ID Age Zipcode Location Illness
1 25 56001 Chennai Diabetes
2 34 56015 Vellore Cancer
3 45 56001 Chennai Flu

Q2. Present with relevant example about the various ways of measuring privacy and utility of anonymized data.

  • Measure privacy: Statistical and Probabilistic methods

  • Probabilistic method: distribution of the data in the original data set and background information about some tuples in the data set.

Answer:

After anonymizing a dataset, organizations must quantify both Privacy Gained and Utility Lost to ensure the released data is both secure and useful.

1. Measuring Privacy

A. Statistical Method: Variance
When noise is added to numerical attributes (perturbation), the variance of the noise indicates how much uncertainty is introduced. A larger variance means the masked values deviate significantly from the original, making it harder for an attacker to guess the true value.
Formula: Variance = (1/n) × Σ(xᵢ – x̄)²
Example: Original salaries: [50K, 60K, 70K, 80K, 90K]. After adding N(0, 5000) noise: [53K, 57K, 75K, 76K, 88K]. Variance of noise = 12.6 million. Higher variance → higher privacy, but potentially lower utility if analysts need precise salary figures.

B. Probabilistic Method
Compares the probability distribution of the original dataset D with the anonymized dataset D'. If distributions are too similar, background knowledge can reveal individual records.
Example: Original disease distribution: Diabetes(40%), Cancer(35%), Flu(25%). If a released group shows Diabetes(80%), Cancer(10%), Flu(10%), an attacker knows an 80% chance any record in that group has Diabetes. Privacy is low when posterior probability P(SD|group) >> prior probability P(SD).

2. Measuring Utility

A. Correlation Preservation: Check if relationships between attributes remain intact. E.g., if original Age and Income correlation = 0.72, anonymized data should show similar correlation.
B. Information Loss Metrics: MSE, MAE, Discernibility Metric, Normalized Certainty Penalty.
C. Classification Accuracy: Train a model on original vs anonymized data. If accuracy drops from 85% to 60%, utility loss is significant.

Q2. Address the possible attacks on the data after applying the below mentioned method using relevant examples.

  • a. k-anonymous [2 Mark]
  • b. l-diverse [4 Mark]
  • c. Perturbation of time series data with white noise [2 Mark]
  • d. Perturbation of time series data with correlated noise. [2 Mark]

Answer:

a. k-Anonymous Data — Homogeneity Attack
Description: k-Anonymity guarantees that each record is indistinguishable from at least k–1 others based on quasi-identifiers. However, it does NOT guarantee diversity in sensitive attributes.
Homogeneity Attack: If all k records in an equivalence class share the same sensitive attribute value, an attacker who can place someone in that class knows their sensitive value with certainty.
Example: A 2-anonymous dataset where both records with (Age 25–30, ZIP 560**) have "Diabetes." An attacker knows their 28-year-old neighbor lives in ZIP 56001 → they know with certainty the neighbor has Diabetes — even without knowing WHICH of the two records is theirs.
Why k-Anonymity fails here: k-Anonymity was designed to prevent identity disclosure, not attribute disclosure. The homogeneity attack is an attribute disclosure attack.

b. l-Diverse Data — Skewness Attack and Similarity Attack
l-Diversity ensures at least l distinct sensitive values per equivalence class. But two attacks still succeed:
Attack 1 — Skewness Attack: Even with l distinct values, if one value appears much more frequently than others, an attacker can infer the sensitive attribute with high probability.
Example: An equivalence class has 10 records with Disease distribution: {Flu: 9, Cancer: 1}. This satisfies 2-diversity (2 distinct values). But an attacker knows with 90% probability that any person in this class has Flu — high probability inference still constitutes privacy loss.
Solution: t-Closeness — requires that the distribution of sensitive values in each class is close to the overall distribution.
Attack 2 — Similarity Attack: The distinct sensitive values are semantically similar, so even with l-diversity, an attacker learns the general category.
Example: l=3 diverse class with Diseases: {Stomach Cancer, Colon Cancer, Liver Cancer}. All three values reveal the person has cancer — even though there are 3 distinct values.
Solution: Semantic l-diversity — requires that the l distinct values are semantically dissimilar (not just lexically distinct).

c. Time Series Perturbation with White Noise — Filtering Attacks
White noise is random, uncorrelated noise added to each time point independently. It is assumed to have a flat frequency spectrum (equal power at all frequencies).
Filtering Attack: An attacker applies a low-pass filter (e.g., moving average, Kalman filter) to the perturbed time series. Since white noise is random and the signal has structure (trends, seasonality), filtering removes the noise and approximately recovers the original signal.
Example: Original monthly sales: [100, 120, 110, 130, 125]. After white noise: [103, 116, 114, 127, 130]. An attacker applies a 3-point moving average → [110, 114, 117] — approximately recovering the trend.
Why it fails: White noise has zero autocorrelation. Frequency-domain filtering separates noise from signal because they occupy different frequency bands.

d. Time Series Perturbation with Correlated Noise — Regression Attacks
Correlated noise is noise where consecutive noise values are related (autocorrelated). Unlike white noise, it has structure — it rises and falls systematically.
Regression Attack: An attacker models the statistical relationship between the perturbed time series and known external variables. Using regression analysis, they estimate the original signal by removing the estimated noise component.
Example: Perturbed hospital admission data has correlated noise added. An attacker who has access to historical hospital data and seasonal patterns uses multiple regression to model the expected admission rate and subtracts the correlated noise model from the observed perturbed data — approximately recovering the original.
Why it fails: Correlated noise has predictable autocorrelation structure. Regression models can estimate and remove this structure.

Q3. Explain the various methods that do not suppress values in the dataset, but alter the values to limit disclosure risk by creating uncertainty around the true values. Most of the methods are based on principles of matrix masking and also applied to both categorical and continuous datasets. [10]

Answer:

1. Noise Addition (Additive Noise Masking)
Definition: Each value x in the dataset is replaced by x + ε, where ε is drawn from a distribution (typically N(0, σ²)). The noise is uncorrelated with the original data.
Matrix masking view: If X is the original data matrix, the masked matrix is X* = X + ε, where ε is the noise matrix.
Applied to: Continuous numerical attributes (age, income, salary).
Example: Original age: [25, 34, 45, 52, 38]. Noise from N(0, 2): [+1.5, –0.8, +2.2, –1.1, +0.9]. Masked age: [26.5, 33.2, 47.2, 50.9, 38.9].

2. Multiplicative Noise
Definition: Each value x is multiplied by a random factor (1 + ε): x* = x × (1 + ε).
Matrix view: X* = X ∘ (1 + ε) where ∘ is element-wise multiplication.
Applied to: Variables where proportional perturbation is more appropriate than additive (e.g., salary: adding a fixed amount to both ₹10,000 and ₹10,00,000 salaries is disproportionate; multiplying by a random factor treats both proportionally).
Example: Salary 50,000 × (1 + 0.03) = 51,500; Salary 5,00,000 × (1 + 0.03) = 5,15,000.

3. Micro-aggregation
Definition: Records are sorted by the value of a sensitive attribute, divided into groups of size ≥ k, and all values within each group are replaced by the group mean (or median).
Matrix view: Within each cluster/group, the column vector is replaced by a constant (the mean vector for numerical attributes).
Applied to: Both continuous (numerical) and grouped ordinal data.
Example: Sorted Incomes: [28K, 30K, 35K, 40K, 45K, 65K]. Groups of 3: [28K, 30K, 35K] → mean = 31K; [40K, 45K, 65K] → mean = 50K. Masked: [31K, 31K, 31K, 50K, 50K, 50K].

4. Rounding
Definition: Continuous values are rounded to the nearest multiple of a base value b. x* = round(x / b) × b.
Applied to: Numerical attributes where slight precision reduction is acceptable (e.g., income rounded to nearest ₹5,000, age rounded to nearest 5).
Example: Income 53,842 → rounded to nearest 5,000 → 55,000.

5. Rank Swapping
Definition: Values are sorted by rank, then randomly swapped between records within a constrained range. A value can only be swapped with another value whose rank is within p percentile points.
Applied to: Numerical continuous attributes.
Example: Salary ranks: S1=30K(1st), S2=35K(2nd), S3=40K(3rd), S4=45K(4th), S5=65K(5th). With 20-percentile constraint (can swap with records within 1 rank): S1 and S2 swap: [35K, 30K, 40K, 45K, 65K].

6. Data Shuffling (Resampling / Shuffling)
Definition: The values of a sensitive attribute are detached from the other attributes and re-randomly attached to different records, preserving the marginal distribution of the sensitive attribute but destroying its relationship with other attributes.
Applied to: Categorical sensitive attributes.
Example: Original: [(Age=30, Disease=Diabetes), (Age=40, Disease=Cancer), (Age=50, Disease=Flu)]. After shuffling Disease column: [(Age=30, Disease=Cancer), (Age=40, Disease=Flu), (Age=50, Disease=Diabetes)]. The age and disease distributions are individually preserved, but their correlation is destroyed.

7. Post-Randomization Method (PRAM)
Definition: For categorical attributes, each value is replaced by another value sampled from a probability distribution defined by a Markov transition matrix M. P(x* = j | x = i) = M[i,j].
Applied to: Categorical variables (Gender, Location, Disease category).
Example: If M[Male, Female] = 0.05 (5% chance of "Male" being changed to "Female"), then in a large dataset, approximately 5% of Male records will be randomly changed to Female, introducing uncertainty.
