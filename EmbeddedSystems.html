Overview of Embedded Systems
Embedded System: A computing system with a dedicated function within a larger mechanical or electrical system. Software (firmware) is embedded into hardware, making it application-specific, real-time, and resource-constrained. Unlike general-purpose computers that run any software, embedded systems are purpose-built.
Feature General Purpose Computer Embedded System
Functionality Versatile, multitasking Single purpose, fixed task
Software General OS, user-installable apps Firmware, dedicated application only
Memory GBs RAM, TBs storage KB–MB RAM, KB–MB Flash/ROM
OS Windows, Linux, macOS RTOS, bare-metal, or no OS
Power 100–500 W mW to a few Watts
Cost (unit) $100–$3000 $0.50–$20
Examples Desktop, Laptop, Server Washing machine, ATM, ECU, Pacemaker
Hard Real-Time: Missed deadline = system failure. Zero tolerance. Examples: Airbag (<30ms), pacemaker, ABS, nuclear plant. Consequences: catastrophic.
Soft Real-Time: Missed deadline = degraded QoS. System continues. Examples: Video streaming, ATM UI, online gaming. Consequences: degraded experience.
Design Challenges

Embedded design involves simultaneous optimization of multiple conflicting metrics — every design is a series of trade-offs.

Metric Description Trade-off
NRE Cost Non-Recurring Engineering — one-time design cost ↑ Custom HW = ↑ NRE but ↓ unit cost
Unit Cost Cost to manufacture each physical copy GPP: low NRE, high unit. ASIC: high NRE, low unit
Performance Throughput and latency — must meet timing deadlines Higher performance = higher power + cost
Power / Energy Battery life, thermal constraints Lower power = slower/less capable
Flexibility Ability to update or reconfigure after deployment More flexible = more overhead (GPP vs ASIC)
Time-to-Market Speed of development and deployment Faster TTM = less optimization = higher cost
Reliability (MTBF) Mean Time Between Failures — 24/7 operation Higher reliability = more redundancy = higher cost
  • Concurrency: Multiple events happen simultaneously — hardware interrupts, sensor reads, and communication compete for CPU.
  • HW/SW Co-design: Hardware and software developed simultaneously — bugs may be in either domain.
  • Verification: Difficult to test — environment is physical and may be dangerous (automotive crash, medical implants).
  • Obsolescence: Products have 10–20 year lifespans — chips may be discontinued before product retires.

PIC (Peripheral Interface Controller): RISC-based MCU family by Microchip Technology. Harvard architecture. Known for ICSP (In-Circuit Serial Programming), built-in ADC, hardware PWM, and 1 instruction / 4 clock cycles efficiency.

PIC advantages over 8051: Built-in Flash (reprogrammable), on-chip ADC (no external chip needed), ICSP (program in-circuit), lower power sleep modes, hardware PWM, 1 instruction per 4 clocks (vs 12 for 8051), larger I/O count.
ARM Architecture
ARM (Advanced RISC Machine): RISC processor family licensed to manufacturers (Apple, Qualcomm, Samsung, ST). Powers 95% of smartphones. Load/Store model: only LDR/STR access memory; all computation in registers. 37 total registers; 16 visible at once (R0–R15).
Cortex-A (Application): High-performance for rich OS (Linux, Android). 32/64-bit. Examples: A53, A72. Smartphones, Raspberry Pi.
Cortex-R (Real-Time): Safety-critical deterministic control. Low bounded latency. Examples: R4, R5. Automotive airbag ECUs, HDD controllers.
Cortex-M (Microcontroller): Ultra-low power embedded. No MMU. Examples: M0, M3, M4, M7. STM32, nRF52, Arduino ARM.

Memory Interfacing
External Memory: When 8051 internal 4KB ROM and 128B RAM are insufficient, external chips are connected. Port 0 carries multiplexed AD0–AD7 (address + data). Port 2 provides A8–A15. ALE pulse triggers 74LS373 latch to capture address, freeing Port 0 for data.

  • Program Memory (ROM) Access: EA=LOW → PSEN=LOW enables external ROM → data on bus → 8051 reads it.
  • Data Memory (RAM) Access: RD pin (P3.7) LOW=read from RAM; WR pin (P3.6) LOW=write to RAM. Use MOVX instruction.
ADC — Analog to Digital Converters
ADC: Converts continuous analog voltage into a discrete N-bit digital number the MCU can process.
Digital Output = (V_in / V_ref) × (2^N − 1)  |  Resolution = V_ref / 2^N
Example: V_in=2.5V, V_ref=5V, N=10 → D = 511
ADC Type Speed Resolution Principle Use Case
Flash ADC Fastest (GHz) Low (6–8 bit) 2^N parallel comparators Oscilloscopes, radar
SAR (Successive Approximation) Medium (1 MHz) 8–16 bit Binary search: tries MSB first each bit MCU on-chip ADC, data acquisition
Sigma-Delta (ΔΣ) Slow (kHz) Very High (16–24 bit) Oversampling + noise shaping Audio, precision instruments
Dual-Slope Very Slow High (12–16 bit) Integrate then de-integrate Multimeters, very accurate sensors

DAC — Digital to Analog Converters
DAC: Converts a digital binary number into a proportional analog voltage or current. Used for audio output, servo control, signal generation.
V_out = V_ref × (D / 2^N)
Weighted Resistor DAC: Resistors R, 2R, 4R, 8R… Each bit controls a switch. Simple but requires precision resistors spanning huge range. Impractical above 8 bits.
R-2R Ladder DAC: Only two resistor values (R and 2R) regardless of bit count. Highly scalable and accurate. Standard in DAC0808. Each additional bit adds just one R and one 2R.

DAC0808: 8-bit current-output DAC using R-2R ladder. Requires external op-amp to convert current→voltage. Settling time ~150ns. Connected directly to 8051 Port 1.

Watchdog Timer (WDT)
WDT: Hardware timer that automatically resets MCU if not "kicked" within a preset timeout period. Safety net against software hang-ups (infinite loops, deadlocks). Normal timer → INTERRUPT. WDT → RESET. Mandatory in safety-critical systems.
  • Normal operation: Program periodically writes specific value to WDT reload register before timeout — "kicking the dog."
  • Fault: If program hangs → WDT not refreshed → WDT overflow → hardware RESET auto-generated.
  • Independent Clock: WDT runs on own internal RC oscillator — works even if main crystal fails.
  • Reset Flag: Status bit set to indicate last reset was WDT-caused → firmware detects and logs the fault.
  • Window WDT: Advanced — WDT must be kicked within a specific time WINDOW (not too early, not too late).

Decoder vs Encoder
Decoder (N→2^N): One of 2^N outputs active — selects a specific peripheral. Encoder (2^N→N): Converts active input to N-bit binary code. Priority Encoder: Multiple inputs active → outputs code for highest-priority active input.

ATM Architecture
ATM (Automated Teller Machine): A special-purpose embedded computing system providing 24/7 self-service banking. Combines secure hardware, real-time software, and encrypted network communication.
Component Function Technology
Host Processor Central controller — coordinates all hardware, manages transactions Industrial x86 embedded PC or ARM SBC
Card Reader Reads mag stripe (Track 1/2) and EMV chip ISO 7816 (chip), ISO 7811 (mag stripe)
PIN Entry Device (PED) Secure encrypted keypad — tamper-evident Hardware Security Module (HSM) inside PED
Cash Dispenser Counts, validates, dispenses banknotes Stepper motors, optical/UV/magnetic sensors
Receipt Printer Prints transaction receipts Thermal dot-matrix printer
Network Module Connects to bank server for authorization Ethernet, leased line, or 4G/LTE modem
ATM Transaction Flow
  1. Card Insert: Card reader scans mag stripe / reads EMV chip.
  2. PIN Entry: PED encrypts PIN with Triple-DES/AES internally — plain PIN NEVER leaves PED hardware.
  3. Authorization Request: ISO 8583 encrypted message sent to bank via TLS-secured network.
  4. Authorization Response: Bank validates PIN, checks balance, sends Approved/Declined code.
  5. Cash Dispensing: Dispenser counts, verifies authenticity (UV/optical), pushes to tray.
  6. Receipt + Journal: Receipt to customer; all details logged to internal journal for audit.
  7. Card Return: Card ejected, session ends.
Leased Line: Dedicated private circuit. Highly reliable, secure, high monthly cost. Bank-branch ATMs.
DSL / 4G Modem: Standard internet with TLS encryption. Lower cost, less reliable. Off-site ATMs.

GPS Receiver Architecture
  • RF Front-End: LNA + bandpass filter → down-converts 1.575 GHz GPS signal to baseband.
  • Correlator DSP: Tracks satellite PRN codes using parallel correlators. Must track ≥4 satellites for 3D fix.
  • Navigation Processor: Solves trilateration — time-of-flight from each satellite → distance → position (lat/lon/alt).

Data Compressor
Data Compression: Encoding information using fewer bits. Critical for embedded to reduce flash storage, transmission bandwidth, memory. Two types: Lossless (perfect reconstruction) and Lossy (data discarded for higher compression).
Type Algorithm Ratio Data Loss Use Case

Huffman Coding 2:1 to 8:1 None Text, file compression (base of ZIP, GZIP)
LZW (Lempel-Ziv-Welch) 2:1 to 4:1 None GIF images, PDF compression, modems

Huffman Coding
  1. Count frequency of each symbol in data.
  2. Build min-heap (priority queue) of frequency nodes.
  3. Merge two lowest-frequency nodes into parent node. Repeat until one tree remains.
  4. Assign 0 to left branches, 1 to right. Traverse tree → each symbol gets variable-length code.
  5. Most frequent symbols get shortest codes (e.g., 'e' → 10). Rare symbols get long codes.
LZW Compression
  1. Initialize dictionary with all single characters (codes 0–255).
  2. Read input; build longest string W present in dictionary.
  3. Output code for W. Add W + next_character to dictionary as new entry.
  4. Both compressor and decompressor build identical dictionaries independently — dictionary NOT transmitted.
Huffman vs LZW
Huffman: statistical — short codes for frequent symbols. LZW: dictionary-based — encodes repeated sequences. JPEG uses DCT (lossy) + Huffman (lossless) at different stages.

JPEG Encoding Pipeline
  1. Color Space Conversion: RGB → YCbCr (Y=luminance, Cb/Cr=chrominance).
  2. Chroma Subsampling (4:2:0): 4 Y samples → only 1 Cb + 1 Cr. Halves color data.
  3. Block Splitting: Image divided into 8×8 pixel blocks.
  4. DCT: Each block converted from spatial to frequency domain.
  5. Quantization (LOSSY): DCT coefficients divided by quantization matrix → many zeros. Quality factor controls aggressiveness.
  6. Zigzag Scan: 8×8 block read in zigzag — groups low-frequency coefficients first.
  7. Huffman Encoding: Run-length encode zeros + Huffman code result. Lossless final step.

💡 Embedded Tips
Use uint8_t instead of int on 8-bit MCUs. Use const for lookup tables (stored in Flash not RAM). Avoid malloc() — use static allocation. Avoid floating-point unless hardware FPU present — use fixed-point arithmetic instead.

Issues & Challenges in Real Time Systems
Priority Inversion: HIGH-priority task indirectly blocked by LOW-priority task. Low holds a mutex that high needs. A MEDIUM task preempts the low task → low cannot release mutex → high waits indefinitely. Famous example: Mars Pathfinder (1997).
Solution — Priority Inheritance: When LOW task holds a resource needed by HIGH task, LOW task temporarily inherits HIGH task's priority — preventing MEDIUM from preempting it. Low finishes, releases resource quickly.
Issue Description Solution
Deadlock Tasks each hold resource the other needs — all blocked forever Resource ordering, timeouts, deadlock detection
Starvation Low-priority task never gets CPU — high always preempts Aging — gradually increase waiting task's priority
Race Condition Two tasks access shared data without sync Mutex, semaphores, atomic operations, disable interrupts
Stack Overflow Task exceeds allocated stack — corrupts adjacent memory Stack canaries, MPU, generous stack sizing
Feature Semaphore Mutex
Purpose Signaling / resource counting (0 to N) Mutual exclusion — binary (0 or 1)
Ownership No owner — any task can signal/wait Owner only — task that locked must unlock
Priority Inheritance Not supported Supported — solves priority inversion

Scheduling Schemes Overview
Algorithm Priority Type Optimal? CPU Utilization Bound Task Type
EDF (Earliest Deadline First) Dynamic — changes as deadlines approach Yes (single CPU) Up to 100% Periodic + Aperiodic
RMS (Rate Monotonic) Static — shorter period = higher priority, fixed Yes (among static) n×(2^(1/n)−1) → 69.3% Periodic only (D=T)
EDF — Earliest Deadline First
EDF: Dynamic priority — task with the EARLIEST absolute deadline gets highest priority at any instant. Priorities recalculated dynamically. Proven optimal for single-processor: if any valid schedule exists, EDF finds it.
Feature EDF
Priority Assignment Dynamic — recalculated at every scheduling event
Optimal? Yes — for single processor. Guarantees no misses if U ≤ 100%
CPU Utilization Up to 100% (theoretical maximum)
Overhead Higher — priority queue reordered dynamically
Predictability Lower than RMS — harder to reason about at design time
EDF Schedulability: ∑(i=1 to n) [C_i / T_i] ≤ 1
C_i = Worst Case Execution Time, T_i = Period
Example: T1(C=2,T=5): 0.4, T2(C=2,T=8): 0.25 → Sum=0.65 ≤ 1 → Schedulable ✓
RMS — Rate Monotonic Scheduling
RMS: Static priority — tasks with shorter periods (higher rates) get permanently higher priorities. Assigned once at design time, never change. Simplest and most widely analyzed real-time scheduling algorithm.
Feature RMS
Priority Assignment Static (fixed forever): shorter period → higher priority
Optimal for Static? Yes — among all fixed-priority algorithms
Utilization Bound n×(2^(1/n)−1) → approaches ln(2) ≈ 69.3% as n→∞
Predictability High — fixed priorities, easy to analyze and certify
Restriction Periodic tasks with implicit deadlines (D_i = T_i) only
RMS Utilization Bound: U_bound = n × (2^(1/n) − 1)
n=1: 100% | n=2: 82.8% | n=3: 78.0% | n→∞: 69.3%
If ∑(C_i/T_i) ≤ U_bound → GUARANTEED schedulable
EDF vs RMS Key Difference
EDF: dynamic priority, optimal (100% utilization), complex implementation. RMS: static priority, optimal among static, simple, safe up to 69.3%. RMS preferred for safety-critical systems (predictable, easy to certify). EDF when high CPU utilization is critical.
Hybrid Scheduling Techniques

Real embedded systems have BOTH periodic tasks (regular sensor reads) AND aperiodic tasks (event-driven). Hybrid techniques combine static and dynamic approaches to handle both optimally.

Technique Description How It Works
Polling Server Simplest server for aperiodic tasks Periodic server (budget C_s, period T_s) checks for aperiodic requests. Unused budget LOST.
Deferrable Server Improvement over polling Unused budget NOT lost — deferred for next aperiodic arrival. Better response time.
Sporadic Server Best for hard aperiodic deadlines Budget replenished only when consumed. Behaves like periodic task to scheduler.
EDF + RMS Mix Hard RT uses RMS; soft uses EDF Two scheduling queues — hard tasks (fixed priority) preempt soft tasks (EDF within window).
eCOS — Embedded Configurable OS
eCOS: Free, open-source, highly configurable RTOS for deeply embedded systems by Cygnus Solutions (now Red Hat). Key feature: Configuration Tool removes ALL unused components — creating a custom minimal kernel. Footprint: as small as 10KB flash + 5KB RAM.
  • Component Framework: Entire OS built from configurable components. Unused components completely excluded from build.
  • Scheduler Options: Bitmap (strict priority), multilevel queue, round-robin within same priority.
  • Sync Primitives: Mutexes, semaphores, condition variables, mailboxes, message queues.
  • POSIX Compatibility: Optional POSIX API layer (pthreads, signals) for code portability.
  • HAL (Hardware Abstraction Layer): Clean separation from hardware. Supports ARM, x86, MIPS, PowerPC.

Protothreads
Protothreads: Extremely lightweight stackless threading for embedded C by Adam Dunkels. Only 2 bytes of RAM per thread. Uses "Duff's Device" (switch/case macro trick) to save and restore execution position across calls. Used in: Contiki OS, IoT nodes with 2KB RAM.
API Macro Description
PT_INIT(&pt) Initialize protothread — reset internal position counter
PT_BEGIN(&pt) Mark start of protothread body
PT_WAIT_UNTIL(&pt, cond) Yield until condition true. Returns to caller; resumes here next call.
PT_YIELD(&pt) Unconditionally yield — resume on next call
PT_END(&pt) Mark end of protothread
Advantages: Tiny footprint (2 bytes/thread). No separate stack. Pure C — no assembly. Works on 8-bit MCUs with 2KB RAM total. Much simpler than full RTOS.
Limitations: No true preemption — cooperative only (must yield voluntarily). Local variables lost across yield. No priority scheduling. Not suitable for hard real-time.

I2C — Inter Integrated Circuit Protocol
I2C: Synchronous, half-duplex, multi-master, multi-slave serial bus using only 2 wires (SDA and SCL). Developed by Philips (now NXP). Each slave has a unique 7-bit or 10-bit address. Pull-up resistors (4.7kΩ typical) required on both lines because the bus is open-drain.
I2C Signal Lines
Signal Direction Function
SDA (Serial Data) Bidirectional (open-drain) Carries address and data bytes. Both master and slave can drive LOW; pull-up resistor pulls HIGH.
SCL (Serial Clock) Master → Slaves (open-drain) Clock signal generated by master. All data transitions happen when SCL is LOW; data sampled when SCL is HIGH.
I2C Bus Speeds
Mode Speed Max Bus Capacitance Pull-up Resistor
Standard Mode (Sm) 100 kHz 400 pF 4.7 kΩ
Fast Mode (Fm) 400 kHz 400 pF 1–2.2 kΩ
Fast Mode Plus (Fm+) 1 MHz 550 pF 0.6–1 kΩ
High-Speed Mode (Hs) 3.4 MHz 100 pF Special current-source pull-up
I2C Transaction Structure
Sequence Bit Pattern Description
START Condition SDA falls while SCL is HIGH Master signals beginning of transaction. All slaves listen.
Address Frame 7 bits address + 1 bit R/W Master broadcasts which slave to talk to. R/W=0 means master will write; R/W=1 means master will read.
ACK/NACK 9th clock — SDA pulled LOW by slave (ACK) or HIGH (NACK) Selected slave acknowledges it received its address. NACK = slave busy or address not recognized.
Data Frames 8 bits data + 1 bit ACK Data transferred MSB first. Each byte acknowledged by receiver.
STOP Condition SDA rises while SCL is HIGH Master signals end of transaction. Bus returns to idle (both HIGH).
Repeated START New START without STOP Master changes direction (read→write or write→read) without releasing bus.

CAN — Controller Area Network
CAN Bus: Robust, differential-signaling serial bus standard designed by Bosch (1986) for automotive and industrial communication. Allows microcontrollers and devices to communicate without a host computer. Uses multi-master, message-based protocol. CAN bus is the backbone of automotive electronics — every modern vehicle uses it to connect 50–100 ECUs.
CAN Electrical Characteristics
Feature Detail
Signaling Differential: CAN_H and CAN_L lines. Difference voltage represents bit state.
Dominant bit (0) CAN_H driven to ~3.5V, CAN_L to ~1.5V. Difference ~2V.
Recessive bit (1) Both lines at ~2.5V (differential ~0V). Bus "releases" — wired-AND logic.
Bus Speed Up to 1 Mbit/s (Classical CAN). CAN FD: up to 8 Mbit/s data phase.
Max Nodes 110 nodes per segment (Classical CAN)
Max Length 40m at 1 Mbit/s; up to 500m at lower speeds
Termination 120Ω resistor at each end of the bus
Noise Immunity Extremely high — differential signaling cancels common-mode noise (EMI from car's ignition, motors)
CAN Frame Structure
Field Bits Description
SOF (Start of Frame) 1 Dominant bit — synchronizes all nodes to start of frame
Arbitration Field 11 or 29 Message identifier. LOWER ID = HIGHER PRIORITY. Non-destructive bitwise arbitration — no collisions!
RTR (Remote Transmission Request) 1 0=data frame; 1=remote frame (requesting data)
Control Field 6 DLC (Data Length Code): 4 bits specifying 0–8 bytes of data
Data Field 0–64 0–8 bytes of data (Classical CAN). Up to 64 bytes in CAN FD.
CRC Field 16 15-bit CRC + 1 delimiter. Error detection for data integrity.
ACK Field 2 Any receiving node pulls bus dominant to acknowledge reception
EOF (End of Frame) 7 7 recessive bits — marks frame end
CAN Non-Destructive Bitwise Arbitration

When multiple nodes transmit simultaneously, each node compares its transmitted bit with the bus state. If a node transmits a recessive bit (1) but sees a dominant bit (0) on the bus, it knows another node with lower ID (higher priority) is transmitting and immediately backs off — no collision, no data loss. The highest-priority message always wins immediately.

CAN Error Detection
  • CRC Check: 15-bit CRC computed by transmitter and all receivers. Mismatch → CRC Error.
  • Bit Monitoring: Transmitter monitors its own transmitted bits. Discrepancy → Bit Error.
  • Bit Stuffing: After 5 consecutive same-polarity bits, a complement bit is inserted. Receiver removes it. Violation → Stuff Error.
  • Form Check: Fixed-format fields checked for correct values → Form Error.
  • ACK Check: Transmitter checks ACK slot — if no dominant bit received → ACK Error.
CAN Node Error States
State Error Count Behavior
Error Active TEC/REC < 128 Normal operation. Node sends Active Error Frames (6 dominant bits)
Error Passive TEC or REC ≥ 128 Still transmits but sends Passive Error Frames (6 recessive bits). Less disruptive.
Bus Off TEC ≥ 256 Node disconnects from bus completely. Recovers after 128 × 11 recessive bits.

RS232 / RS485
RS232 Standard
RS232 (EIA-232): Standard for asynchronous serial communication over short distances. Defines voltage levels: +3V to +15V = Logic 0 (SPACE), −3V to −15V = Logic 1 (MARK). Logic levels are inverted and much larger than TTL (0/5V) — requires level shifters (MAX232 IC) to interface with MCU.

Speed Up to 115.2 kbps (practically) Up to 35 Mbit/s
Distance Up to 15m (at low speeds) Up to 1200m
Noise Immunity Low — single-ended, susceptible to EMI Very High — differential signaling cancels noise

🔔 Level Shifter
8051/PIC/ARM I/O pins use TTL levels (0V/5V or 0V/3.3V). RS232 uses ±12V. A level shifter IC like MAX232 (for RS232) or MAX485 (for RS485) is ALWAYS needed between the MCU UART pins and the RS232/RS485 connector.
Bluetooth
Bluetooth (IEEE 802.15.1): Short-range wireless technology for Personal Area Networks (PANs). Operates in 2.4 GHz ISM band. Uses frequency hopping spread spectrum (FHSS) — hops through 79 channels at 1600 hops/second to avoid interference. Two major variants: Classic Bluetooth and BLE (Bluetooth Low Energy).

Bluetooth Architecture Layers
  • Radio Layer: 2.4 GHz GFSK modulation, FHSS with 79 (classic) or 40 (BLE) channels.
  • Baseband / Link Controller: Manages connection establishment, packet format, FEC, error detection.
  • Link Manager Protocol (LMP): Handles authentication, encryption, power management, and link setup.
  • HCI (Host-Controller Interface): Standardized interface between host (OS) and controller (BT chip).
  • L2CAP: Logical Link Control and Adaptation Protocol — multiplexes upper-layer protocols.
  • RFCOMM: Cable replacement (serial port emulation over Bluetooth — SPP profile).
  • GATT (Generic Attribute Profile): BLE services and characteristics architecture (heart rate service, battery service, etc.).

Zigbee
Zigbee (IEEE 802.15.4): Low-power, low-data-rate wireless mesh networking protocol for IoT and sensor networks. Designed for applications requiring long battery life (years) and large-scale mesh networks with hundreds of nodes. Operates at 2.4 GHz (global) and 868/915 MHz (regional).

Zigbee End Device (ZED) Leaf node — only communicates with its parent router. Can sleep deeply to save power. Battery — can sleep for years

Role in Agriculture Sector — Smart/Precision Agriculture
Smart Agriculture: The application of IoT, embedded systems, and data analytics to optimize agricultural processes — maximizing yield while minimizing resource consumption (water, fertilizer, pesticide). Also called Precision Agriculture or AgriTech.
Smart Irrigation System

Traditional irrigation wastes up to 60% of water. A smart irrigation system uses embedded sensors to irrigate only when and where needed.

  1. Sensors: Soil moisture sensors (capacitive or resistive), temperature/humidity sensors (DHT22), rain gauges, wind sensors deployed across the field.
  2. Data Acquisition: Sensors connected to embedded MCU nodes (Arduino/ESP32). ADC reads analog sensor values.
  3. Processing: MCU compares soil moisture against threshold values. If moisture < threshold → activate irrigation.
  4. Actuation: MCU drives relay module → opens/closes motorized water valves (solenoids) for specific field zones.
  5. Connectivity: ESP32 sends sensor data via WiFi/LoRa to cloud server or local gateway. Farmer monitors via mobile app.
  6. Optional: Weather API integration: If rain is forecast, system delays irrigation automatically.

LoRa (Long Range) for Agriculture

Agricultural fields can span hundreds of hectares. WiFi (50m range) and BLE (40m range) are inadequate. LoRa (Long Range) is a low-power wide-area network (LPWAN) technology specifically designed for IoT in rural environments:

  • Range: 2–15 km in rural areas (line of sight), up to 30 km with high-gain antennas.
  • Power: Ultra-low — nodes can run for 10+ years on AA batteries.
  • Data Rate: 0.3–50 kbps — sufficient for sensor readings.
  • LoRaWAN: Network protocol layer on top of LoRa physical layer. Defines star-of-stars topology (nodes → gateways → network server → cloud).
  • Modules: SX1276 (Semtech), RFM95W, RAK811 — add LoRa to any MCU via SPI.

Fuzzy Logic in Consumer Appliances
Fuzzy Logic: A control technique that uses approximate rather than binary (yes/no) reasoning. Instead of "water level IS HIGH or NOT HIGH," fuzzy logic handles "water level is SOMEWHAT HIGH." This allows washing machines, rice cookers, and air conditioners to make more nuanced control decisions based on multiple imprecise sensor inputs — producing better results than simple threshold-based control.
PWM in Consumer Electronics
  • LED Dimming: PWM frequency >100Hz prevents flicker perception. 8-bit PWM = 256 brightness levels.
  • Motor Speed Control: Fan speed in laptops (PWM drives MOSFET → motor current control).
  • Audio Amplification: Class-D amplifiers use high-frequency PWM to encode audio — highly efficient (90%+).
  • DC-DC Converters: Switch-mode power supplies (SMPS) use PWM to regulate output voltage efficiently.
Industrial Controls
Industrial Embedded Systems: Control and automation systems used in manufacturing, process control, and infrastructure. Characterized by extreme reliability requirements, harsh environmental conditions, long lifecycles (10–30 years), hard real-time response, and high electromagnetic interference (EMI) tolerance.
PLC — Programmable Logic Controller
PLC: The workhorse of industrial automation. A ruggedized computer specifically designed for industrial control tasks. Unlike a general MCU, a PLC has a highly reliable design with watchdog timers, redundant power supplies, and a deterministic scan cycle. Programmed using IEC 61131-3 standard languages (Ladder Diagram, Structured Text, Function Block Diagram).
PLC Component Function
CPU Module Executes user program cyclically. Scan cycle: read inputs → execute logic → write outputs. Deterministic timing.
Digital I/O Modules Opto-isolated inputs (24VDC sensors) and relay/transistor outputs for actuators. Up to 1000+ I/O points.
Analog I/O Modules 4–20mA (industrial standard) or 0–10V analog input/output for sensors and variable-speed drives.
Communication Module Profibus, Profinet, EtherNet/IP, Modbus TCP — connects to SCADA, HMI, other PLCs, drives.
Power Supply Converts 120/240VAC to 24VDC for PLC and field devices. Often redundant (N+1).
Programming Device PC with IEC 61131-3 software (Siemens TIA Portal, Allen-Bradley Studio 5000, etc.)
SCADA — Supervisory Control and Data Acquisition
SCADA: A large-scale supervisory system that monitors and controls an entire industrial plant, pipeline, power grid, or water treatment facility in real-time. A SCADA system collects data from PLCs and RTUs via industrial networks, displays it on operator HMI screens, and allows supervisory control and alarm management.
SCADA Component Function
RTU (Remote Terminal Unit) Collects sensor data from geographically distributed field devices (e.g., pipeline sensors). Communicates with SCADA server via radio/satellite/cellular.
PLC (local level) Executes local control logic in real-time. Reports status to SCADA server.
HMI (Human Machine Interface) Operator touchscreen/panel showing real-time process status, trends, alarms. Built-in embedded PC running HMI software.
SCADA Server Central data historian, alarm management, report generation, network management.
Engineering Workstation PC for configuring PLCs, SCADA, and HMI — not used for real-time control.

Key Design Requirements for Medical Embedded Systems
  • Fail-Safe Design: System must fail into a safe state, not an unsafe one. Watchdog timer mandatory. Dual-channel safety circuits for Class C devices.
  • EMC Compliance: Must function correctly in hospital environment (MRI, electrosurgery, radio equipment). IEC 60601-1-2 electromagnetic compatibility standard.
  • Electrical Safety: Patient-applied parts (electrodes, probes touching patient) must meet strict leakage current limits (<10μA for cardiac-floating type CF equipment).
  • Power Backup: Critical devices must operate for minimum time on backup battery if AC power fails. Ventilators: ≥30 minutes. Monitors: ≥2 hours.
  • Alarm System: IEC 60601-1-8 defines alarm priority (high/medium/low), sound levels (45–85 dBA), and required response times for medical alarms.
  • Data Logging: All device events, alarms, and therapy deliveries must be logged with timestamp — essential for clinical audit and incident investigation.
  • Cybersecurity: Network-connected medical devices (infusion pumps, patient monitors) must be secure against hacking — FDA guidance on medical device cybersecurity.
ECG Signal Processing Pipeline
  1. Electrode Placement: Ag/AgCl electrodes on patient skin capture biopotential signals (0.5–5mV amplitude, 0.05–150Hz bandwidth).
  2. Instrumentation Amplifier: AD8232 or INA128 — high CMRR (>100dB) to reject 50/60Hz powerline noise while amplifying differential ECG signal by 100–1000×.
  3. Anti-Aliasing Filter: Low-pass filter at <150Hz before ADC to prevent aliasing. Notch filter at 50Hz or 60Hz.
  4. ADC: 12–16 bit ADC at 250–1000 samples/second per lead. 12-lead ECG = 12 simultaneous channels.
  5. Digital Signal Processing: Baseline wander removal (high-pass filter >0.05Hz), R-wave detection (Pan-Tompkins algorithm), heart rate calculation, arrhythmia detection.
  6. Display & Analysis: Waveform rendered on screen. Automatic QRS, ST-segment, QT-interval measurement. Alarm if heart rate outside range.

ADC / DAC

Machine Cycle = 12 / f_osc  |  Delay = (65536 − TH:TL) × Machine_Cycle
f=11.0592 MHz → MC = 1.085 μs  |  50ms delay → TH:TL = 65536 − 46083 = 4BFDH

UART Baud Rate
TH1 (Mode 2 Timer1) = 256 − [f_osc / (384 × Baud_Rate)]
f=11.0592 MHz, 9600 bps → TH1 = 256 − 3 = 253 = 0xFDH  (this f_osc chosen so TH1 is exact integer)

Module High Priority Topic Key Facts to Remember
M1 8051 architecture 4KB ROM, 128B RAM, 4 ports, 2 timers, 1 UART. EA pin: HIGH=internal ROM, LOW=external. ALE latches address from P0.
M1 Harvard vs Von Neumann Harvard = separate code + data buses (8051, PIC). Von Neumann = shared bus (x86). Harvard is faster (parallel fetch).
M1 RISC vs CISC RISC=simple, fixed-length, 1 cycle/instr, load/store (ARM, PIC). CISC=complex, variable-length, multi-cycle (x86, 8051).
M2 Timer modes (8051) Mode 1: 16-bit, manual reload (longest delay). Mode 2: 8-bit auto-reload (UART baud rate). C/T bit: 0=timer, 1=counter.
M2 WDT Timer → interrupt. WDT → RESET. Must "kick" WDT periodically. Detects infinite loops/deadlocks. Runs on independent clock.
M2 8051 interrupts EA=global enable. Vectors: INT0=0003H, T0=000BH, INT1=0013H, T1=001BH, Serial=0023H. Natural priority: INT0>T0>INT1>T1>Serial.
M2 UART baud rate formula TH1 = 256 − [f_osc/(384 × Baud)]. Use f=11.0592MHz for exact integer TH1 values. 9600 bps → TH1=0xFD.
M3 ATM transaction flow Card insert → PIN encrypted in PED (HSM) → ISO 8583 auth request → bank response → cash dispense → receipt → card return.
M3 JPEG pipeline RGB→YCbCr → Chroma subsample (4:2:0) → 8×8 blocks → DCT → Quantization (LOSSY HERE) → Zigzag → Huffman encode.
M3 Huffman vs LZW Huffman: statistical (short code for frequent symbols). LZW: dictionary-based (repeated sequences). Both lossless. JPEG uses DCT+Huffman.
M4 Code optimization techniques Dead code elimination, constant folding, loop unrolling, strength reduction (×2 → <<1), function inlining, register variables.
M4 JTAG pins TCK (clock), TMS (mode select), TDI (data in), TDO (data out). SWD uses only 2 pins (SWDCLK + SWDIO) — ARM alternative.
M5 EDF vs RMS EDF: dynamic, optimal, 100% utilization. RMS: static (shorter period=higher priority), optimal for static, ≤69.3% bound. RMS preferred for safety-critical.
M5 Priority inversion LOW holds mutex HIGH needs. MEDIUM preempts LOW → HIGH waits indefinitely. Solution: Priority Inheritance (LOW inherits HIGH's priority).
M5 Semaphore vs Mutex Semaphore: signaling, no ownership. Mutex: mutual exclusion, has ownership, supports priority inheritance. Use mutex for shared data, semaphore for signaling.
M5 Protothreads 2 bytes RAM per thread. Stackless. Cooperative only (no preemption). Uses Duff's Device (switch/case). Not suitable for hard RT. Adam Dunkels.

🌟 Top 10 Most Exam-Important Points

  1. 8051: ALE, PSEN, EA functions — ALE latches A0–A7 from P0. PSEN enables external ROM. EA=LOW→always external ROM.
  2. Timer Mode 2 — 8-bit auto-reload. TH1 used as reload value → automatically reloaded after each overflow. Used for UART baud rate generation.
  3. WDT — Timer generates INTERRUPT. WDT generates RESET. Must kick periodically. Detects hangs.
  4. Priority Inversion + Solution — HIGH blocked by LOW holding mutex. MEDIUM preempts LOW. Fix: Priority Inheritance.
  5. EDF: ∑(C_i/T_i) ≤ 1 = schedulable. RMS: ∑(C_i/T_i) ≤ n×(2^(1/n)−1) → 69.3%.
  6. I2C transaction — START → 7-bit address + R/W → ACK → data → ACK → STOP. Open-drain, pull-up resistors required.
  7. CAN arbitration — Lower ID wins. Non-destructive. Dominant=0 wins over Recessive=1. No collisions.
  8. JPEG compression — DCT converts spatial→frequency. QUANTIZATION is the only LOSSY step. Huffman at end is lossless.
  9. Huffman (statistical) vs LZW (dictionary) — Both lossless. Huffman needs frequency table. LZW builds dictionary on-the-fly at both ends.
  10. Medical Class C devices — Highest rigor (pacemaker, defibrillator, ventilator). WDT mandatory. Fail-safe design. IEC 62304 + FDA approval.
