Q1. Classify an embedded system in three distinct ways based on performance and exemplify how its applications differ from those of conventional computer systems. Analyse hardware, software, and design constraints. 10 Marks

Answer — Embedded System Classification & Comparison

Hardware Constraints

  • Processor Speed: 8–32 MHz (8051) vs 4+ GHz desktop. Far limited computational power.
  • Memory: RAM in bytes to KB. 8051: 128B RAM, 4KB ROM. Desktop: GB RAM, TB storage.
  • Power: Battery-operated; sleep modes reduce current to µA. No fans/cooling allowed.
  • Size/Form factor: PCB must fit inside the product. Custom ASIC or off-the-shelf MCU chosen for footprint.
  • I/O Ports: Limited GPIOs, ADC channels, timer peripherals — must be carefully allocated.
  • Environmental: Must survive -40°C to +125°C, vibration, humidity, EMI.

Software Constraints

  • Limited memory: Code must be compact; no dynamic memory allocation. Use static arrays.
  • RTOS overhead: Kernel must be lightweight — FreeRTOS = 6–12 KB vs Linux kernel = 10 MB+.
  • No virtual memory: Must manage physical RAM directly; no swap space.
  • Language: C and Assembly. C++ limited. No interpreted languages (Python too slow/large).
  • Interrupt-driven: Must handle ISRs within strict latency bounds.
  • Reliability: Software must never crash. Watchdog timer resets system if software hangs.

Design Constraints

  • Cost: BOM often <$1–$5. Every byte of ROM has a cost implication.
  • Time-to-market: Use proven MCU families and reference designs.
  • Certification: Medical (FDA), Automotive (ISO 26262), Aviation (DO-178C) require formal verification.
  • Power budget: Battery life directly tied to MIPS/mW efficiency.
  • Thermal: No cooling fans; must stay within junction temperature using careful PCB layout.
  • Maintainability: Firmware updates via OTA, JTAG/SWD in the field.
📝 Exam Tip: Always give the three classification axes: Performance/Complexity, Time-Criticality, Functionality. Key phrase: "Embedded systems are purpose-built, resource-constrained, and time-critical." Hard vs soft real-time is a favourite exam distinction.

Q3. Explain the operation of an R-2R ladder DAC in embedded systems when a 3-bit DAC is given a binary code of 101. Include a neat sketch. 10 Marks

Answer — R-2R Ladder DAC for Input 101

What is R-2R Ladder DAC?

R-2R Ladder DAC converts digital binary input to proportional analog voltage using only two resistor values — R and 2R — arranged in a ladder network. Preferred over binary-weighted DACs because it uses only two resistor values, making precision manufacturing easier.

Circuit — 3-bit R-2R Ladder

D2 (MSB=1) D1 (=0) D0 (LSB=1) │ │ │ 2R 2R 2R │ │ │ ───┤──────R───────┤──────R───────┤────── Vout │ │ │ 2R 2R 2R │ │ │ GND GND GND Switch logic: bit=1 → connect to Vref; bit=0 → connect to GND Thevenin analysis for input 101: D2=1 (Vref): contributes Vref/2 D1=0 (GND): contributes 0 D0=1 (Vref): contributes Vref/8 Vout = Vref/2 + 0 + Vref/8 = 4Vref/8 + Vref/8 = 5Vref/8

Calculation for 101

D2=1 (MSB), D1=0, D0=1 (LSB) → Decimal value = 5

Vout = Vref × (D2×4 + D1×2 + D0×1) / 2³
Vout = Vref × (1×4 + 0×2 + 1×1) / 8 = Vref × 5/8

If Vref = 5V: Vout = 5 × 5/8 = 3.125 V

Truth Table — All 3-bit Inputs (Vref = 5V)

D2 D1 D0 Decimal Vout
0 0 0 0 0.000 V
0 0 1 1 0.625 V
0 1 0 2 1.250 V
0 1 1 3 1.875 V
1 0 0 4 2.500 V
1 0 1 5 3.125 V ← Answer
1 1 0 6 3.750 V
1 1 1 7 4.375 V

R-2R vs Binary-Weighted DAC

R-2R Advantages:
• Only 2 resistor values (easy to match)
• Better accuracy (tight tolerance)
• Easily extended to more bits
• Used in audio DACs, function generators
Binary-Weighted Issues:
• Needs 2ⁿ ratio (e.g., 128:1 for 8-bit)
• High-value resistors are inaccurate
• Impractical for high-resolution DACs
📝 Exam Tip: Universal formula: Vout = Vref × (decimal value) / 2ⁿ. For 3-bit: divide by 8. For 4-bit: divide by 16. Draw ladder with R horizontal (series) and 2R vertical (shunt) clearly labelled. Each bit's Thevenin contribution: MSB = Vref/2, next = Vref/4, LSB = Vref/8.

Timing Diagram & Operation

TRIG: _____|‾‾‾‾‾‾‾|_________________________ ←10µs→ (8051 sets P1.0 HIGH for 10µs, then LOW) HC-SR04 transmits 8 × 40kHz ultrasonic bursts ECHO: _____________|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|________ ←──── T_echo ────→ (proportional to distance) Distance (cm) = T_echo(µs) × Speed_of_sound / 2 = T_echo(µs) × 0.034 / 2 = T_echo(µs) / 58.8

Critical Steps

1
Send Trigger Pulse: Set P1.0 HIGH for exactly 10 µs, then LOW. Causes HC-SR04 to emit 8 pulses at 40 kHz.
2
Wait for Echo HIGH: Poll P1.1 until it goes HIGH. Start Timer 0 immediately when it does.
3
Measure Echo Width: Keep Timer 0 running while P1.1 is HIGH. Stop timer when Echo goes LOW.
4
Calculate Distance: Read TH0:TL0, multiply by 1.085µs (machine cycle at 11.059MHz). Apply formula.
5
Display & Repeat: Show distance on LCD. Add 60ms delay before next measurement (to avoid false echoes).

8051 C Program

#include <reg51.h>
sbit TRIG = P1^0;
sbit ECHO = P1^1;

void delay_10us() {
    unsigned char i = 9; while(i--); // ~10µs at 11.059MHz
}

unsigned int measure_echo() {
    TMOD = 0x01; TH0 = 0; TL0 = 0;
    while(ECHO == 0);   // Wait for Echo HIGH
    TR0 = 1;            // Start Timer
    while(ECHO == 1) {  // Wait for Echo LOW
        if(TH0 > 0x8B) break; // Timeout ~38ms
    }
    TR0 = 0;
    return (TH0 * 256 + TL0);
}

float get_distance_cm(unsigned int count) {
    // count * 1.085µs = time in µs
    // Distance = time_µs * 0.034 / 2
    return (count * 1.085 * 0.034) / 2.0;
}

void main() {
    float d; unsigned int t;
    TMOD = 0x01;
    while(1) {
        TRIG = 1; delay_10us(); TRIG = 0; // Trigger
        t = measure_echo();
        d = get_distance_cm(t);
        // display_lcd(d); // LCD display code
    }
}

Distance Formula

Speed of Sound = 343 m/s = 0.034 cm/µs

Distance = Echo_pulse_width_µs × 0.034 / 2 (cm)
OR simplified: Distance = Echo_pulse_width_µs / 58.8 (cm)

Division by 2 because ultrasound travels TO object AND BACK (round trip)
📝 Exam Tip: Always mention the division by 2 — ultrasound travels round trip. Timeout condition: if Echo > 38ms → no object within 400cm range. At 11.059MHz: 1 machine cycle = 1.085µs. Timer count × 1.085 = time in µs.

Q6. Illustrate five code optimization techniques, providing relevant examples for each. 10 Marks

Answer — Five Code Optimization Techniques

Code optimization transforms program code to improve execution speed, reduce memory usage, and decrease power consumption — critical in embedded systems with constrained resources (limited ROM, RAM, CPU cycles).

1. Loop Unrolling

Replaces loop with explicit repeated body to eliminate loop overhead (increment, compare, branch).

❌ Before (with loop): 

for(int i=0; i<4; i++)
  sum += arr[i];
// 4 iter × (compare+branch+increment) 
// = 12 extra instructions

✅ After (unrolled): 

sum = arr[0]+arr[1]
    + arr[2]+arr[3];
// 0 loop overhead instructions
// ~25% faster for short loops

2. Strength Reduction

Replaces expensive operations (multiply, divide) with cheaper equivalents (bit shifts).

❌ Before (expensive): 

x = y * 4;   // MUL = 4+ cycles
x = y / 8;   // DIV = 20+ cycles
x = y * 32;  // MUL instruction

✅ After (fast shifts):

x = y << 2; // LEFT SHIFT = 1 cycle
x = y >> 3; // RIGHT SHIFT = 1 cycle
x = y << 5; // Still 1 cycle!

3. Constant Folding / Propagation

Evaluates constant expressions at compile time rather than runtime.

❌ Before (runtime calc):

int cycles = 12*1000*1000/12;
// Computed at runtime: 3 MUL+DIV
// Every time this line executes!

✅ After (compile-time):

#define CYCLES 1000000UL
// Compiler resolves to constant
// 0 runtime arithmetic needed

4. Dead Code Elimination

Removes code that never executes or whose result is never used.

❌ Before (dead code): 

int debug_mode = 0;
if(debug_mode) {
  uart_printf("Debug..."); // NEVER runs
  // But still occupies ROM!
}
int x = compute(); // x never used

✅ After:

#ifdef DEBUG
  uart_printf("Debug...");
#endif
// Compile-time removal
// Saves ROM + removes string constant

5. Function Inlining

Replaces function call with function body, eliminating call/return overhead.

❌ Before (function call):

int square(int x){return x*x;}
// 8051: ACALL(2B,2cy)+RET(1B,2cy)
// + stack push/pop = 8+ cycles
// per call

✅ After (inline): 

static inline int square(int x)
  { return x*x; }
// GCC replaces call with body
// No function call overhead
// ~8 cycles saved per use

Summary Table

Technique Reduces Trade-off Best For
Loop Unrolling Loop overhead instructions Increases code size Fixed-count loops, ISRs
Strength Reduction MUL/DIV cycles Readability Scaling, indices, timing
Constant Folding Runtime computations None Hardware constants, baud rates
Dead Code Elimination ROM size, cache pressure None Debug code, unused features
Function Inlining Call/return overhead Code size increase Short frequently-called functions
📝 Exam Tip: Write BEFORE and AFTER code for each technique — examiners give full marks only when transformation is shown. Mention which resource is saved: ROM, RAM, or CPU cycles. Other valid techniques: register variables (register int i), volatile keyword, bit manipulation, lookup tables replacing computation.

Answer — Hybrid Scheduler & EDF Task Timeline

A Hybrid Scheduler combines EDF (Earliest Deadline First) for dynamic priority assignment with RMS (Rate Monotonic) for periodic tasks — handling both periodic and aperiodic tasks with deadline guarantees in a single system.

Requirements of a Real-Time Hybrid Scheduler

Requirement Description
Deadline Awareness Knows absolute deadline of each task; uses EDF for dynamic priority
Preemptability Higher-priority task immediately preempts running lower-priority task
Context Switching Save/restore CPU registers, PC, SP when switching tasks (low latency)
Schedulability Test EDF: U = Σ(Ci/Ti) ≤ 1; RMS: U ≤ n(2^(1/n)−1) ≈ 0.69 for n→∞
Aperiodic Handling Aperiodic tasks in background; served when periodic tasks are idle
Priority Inheritance Prevent priority inversion (low-priority task holding mutex needed by high-priority)
Tick Resolution Timer ISR period ≤ min burst time for accurate scheduling decisions

Q9b. How does I2C protocol handle device addressing, and what strategies can be employed to manage potential address conflicts in a system with multiple I2C devices? 10 Marks

Answer — I2C Device Addressing & Conflict Management

I2C (Inter-Integrated Circuit) is a two-wire protocol (SDA + SCL) with master-slave architecture. Each slave has a unique 7-bit or 10-bit address. Master initiates all transactions by sending the device address first.

7-bit Addressing (Standard Mode)

I2C Address Byte (8 bits total): ┌───┬───┬───┬───┬───┬───┬───┬───┐ │A6 │A5 │A4 │A3 │A2 │A1 │A0 │R/W│ └───┴───┴───┴───┴───┴───┴───┴───┘ MSB ←────── 7-bit Address ──────→ R/W bit Address range: 0x00–0x7F = 128 addresses Reserved: 0x00 (general call), 0x01–0x07 (special) Available: 0x08–0x77 = 112 usable device addresses Transaction sequence: [START][ADDR(7-bit)+R/W][ACK][DATA][ACK][...][STOP]

10-bit Addressing (Extended)

First byte: 11110 A9 A8 R/W (prefix 11110xx marks 10-bit mode) Second byte: A7 A6 A5 A4 A3 A2 A1 A0 Total range: 0x000 to 0x3FF = 1024 addresses

Address Conflict Strategies

S1
Hardware Address Pins (Simplest). Many ICs have A0/A1/A2 address select pins. Connect to VCC or GND to change address. E.g., 4 × PCF8574 at 0x20, 0x21, 0x22, 0x23 by wiring A0,A1 differently. Allows up to 8 instances of same IC.
S2
I2C Multiplexer/Switch — TCA9548A. Provides 8 independent I2C buses. Write channel select byte to TCA9548A (0x70–0x77), then talk to device on that channel. Allows 8 × same-address devices. Used for multiple identical sensors.
S3
Multiple Hardware I2C Buses. Modern MCUs (STM32, ESP32) have 2–4 independent I2C peripherals. Place conflicting devices on separate I2C bus instances (I2C1, I2C2, I2C3). Each fully independent.
S4
I2C Bus Isolator / Switch (GPIO-controlled). Use GPIO to selectively connect/disconnect a device from the bus. Only selected device active at a time — creates separate bus segments with one GPIO per device group.
S5
Software (Bit-bang) I2C on Different GPIO Pairs. Implement I2C in software using any two GPIOs. Each software I2C instance has its own address space. Useful on MCUs with limited hardware I2C peripherals.

ADC — Analog to Digital Converter

ADC converts a continuous analog voltage into a discrete binary number proportional to input voltage. Used to bring real-world analog signals into digital processors.
Characteristic Description Example (ADC0804)
Resolution Bits → determines smallest measurable step 8-bit → 256 steps
Step size Vref / 2ⁿ 5V/256 = 19.5 mV/step
Sampling Rate Max samples/sec (Nyquist: ≥ 2× signal freq) 10,000 samples/sec
Conversion Time Time to complete one conversion 100 µs
Input Range Voltage range accepted 0–5 V
Accuracy ±½ LSB typical ±10 mV at 5V reference
N = (Vin / Vref) × (2ⁿ − 1)
For ADC0804 (8-bit, Vref=5V): N = (Vin/5) × 255
Example: Vin = 3.5V → N = (3.5/5)×255 = 178 = 0xB2

SAR ADC Working Principle:

  1. SAR register starts with MSB=1, all others 0 (guess = Vref/2)
  2. Internal DAC converts SAR value to voltage; comparator checks vs Vin
  3. If Vin > DAC output → keep bit=1; else bit=0
  4. Repeat from MSB to LSB (n steps for n-bit ADC)
  5. Final SAR value = digital equivalent of Vin

ADC Types: Flash ADC (fastest, uses 2ⁿ–1 comparators), SAR ADC (most common), Sigma-Delta ADC (highest resolution, audio).

ADC Applications: Temperature monitoring, battery voltage, audio sampling, medical instruments, industrial sensors.

DAC — Digital to Analog Converter

DAC converts binary digital values back into proportional analog voltage. Used to drive actuators, generate waveforms, and control analog systems from digital processors.
Characteristic Description
Resolution 8-bit = 256 steps; 12-bit = 4096 steps; 16-bit = 65536 steps
Output voltage Vout = (Digital_Input / 2ⁿ) × Vref
Settling time Time to reach and stabilize at final voltage after input change
Linearity (DNL) Differential Non-Linearity: deviation from ideal 1 LSB step
Monotonicity Output always increases when input increases (essential requirement)
Glitch energy Unwanted transient during code transitions

DAC Types: R-2R Ladder (only 2 resistor values, accurate), Binary-Weighted Resistors (simple but impractical for high resolution), Current Steering (high-speed audio).

DAC Applications: Motor speed control, audio generation, function generators, control system setpoints, waveform synthesis.

📝 Exam Tip: ADC formula: Step size = Vref / 2ⁿ. For DAC: Vout = (D/2ⁿ) × Vref. Sample & Hold (S/H) circuit is essential before ADC — prevents signal changing during conversion (aperture error). Nyquist theorem: sample at ≥ 2× highest signal frequency to avoid aliasing.

Answer — Logic Analyser & CDFG for Control Structures

Logic Analyser captures and displays multiple digital signals simultaneously over time. Used to debug embedded software, verify timing, and decode digital protocols (UART, SPI, I2C, CAN). Captures binary (0/1) states with precise timestamps — unlike an oscilloscope which shows analog voltage waveforms.
  • Channels: 8–256 simultaneous digital input channels
  • Sample rate: Up to 500 MHz+; stores millions of samples
  • Trigger modes: Edge, pattern, protocol-specific trigger
  • Protocol decoding: Built-in UART, SPI, I2C, CAN, I2S decoders
  • Use in embedded: Verify GPIO timing, debug interrupt latency, test comm buses

CDFG (Control Data Flow Graph): Extends DFG with decision nodes, loops, branches. Diamond = condition; Rectangle = operation; Back edge = loop. Used for compiler optimization and hardware synthesis.

(i) Embedded Program Translation Phases

1
Source Code (.c / .asm): Human-readable C or Assembly. Written in IDE (Keil µVision, MPLAB, Eclipse). Contains program logic, peripheral config, includes header files.
2

(ii) 8051 Timer 0 Mode 2 — Toggle P2.5 Every 270ms

Timer 0 Mode 2 is 8-bit auto-reload mode. When timer overflows (FF→00), it automatically reloads TH0 into TL0. No manual reload needed — ideal for generating periodic interrupts or delay loops.
XTAL = 11.059 MHz → Machine cycle = 1.085 µs

Mode 2 is 8-bit: max count = 256
TH0 reload value = 256 − (desired_count)

For 270ms total (135ms per half-period — toggle every 270ms means:
delay needed = 270ms)

Since Mode 2 max is 256×1.085µs = 277.76 µs per overflow,
we need a loop counter:

270ms = 270000µs / 1.085µs = 248848 machine cycles
Divide: 248848 / 256 = 972 overflows

Timer value = 256 − 256 = 0x00 → TH0 = 0x00 (max 277µs period)
Loop 972 times for 270ms total delay
#include <reg51.h>
sbit P2_5 = P2^5;  // Only pin P2.5

// Timer 0 Mode 2 (8-bit auto-reload) delay
// TH0=0x00 → period = 256 × 1.085µs = 277.76µs per overflow
// 270ms / 277.76µs = ~972 overflows

void delay_270ms() {
    unsigned int count = 0;
    TMOD = 0x02;   // Timer 0, Mode 2 (8-bit auto-reload)
    TH0  = 0x00;   // Reload value = 256-256 = 0 (max period)
    TL0  = 0x00;   // Initial count = 0
    TR0  = 1;      // Start Timer 0
    while(count < 972) {      // Wait for 972 overflows = ~270ms
        while(TF0 == 0);      // Wait for overflow
        TF0 = 0;               // Clear overflow flag (auto-reload happens!)
        count++;
    }
    TR0 = 0;       // Stop timer
}

void main() {
    // Configure P2: initially all HIGH (quasi-bidirectional)
    P2 = 0xFF;
    TMOD = 0x02;
    while(1) {
        P2_5 = ~P2_5;   // Toggle ONLY P2.5 (other pins unchanged)
        delay_270ms();
    }
}

// ‾‾‾‾‾‾‾‾‾‾‾‾‾|_____________|‾‾‾‾‾‾‾‾‾‾‾‾|_____
//   ←─ 270ms ─→ ←── 270ms ──→ ←── 270ms ──→
// Toggle period = 270ms (full cycle = 540ms)

Q1. How do the different execution modes in ARM architecture optimize system performance, enable efficient multitasking, and ensure robust security in embedded and real-time applications? 10 Marks

Answer — ARM Execution Modes

ARM architecture defines 7 processor operating modes (plus TrustZone secure/non-secure worlds in ARMv8). Each mode has its own banked registers — ensuring that mode switches don't corrupt running context. This enables preemptive multitasking and hardware-enforced security in embedded systems.

ARM Operating Modes — Complete Table

Mode Encoding (M[4:0]) Triggered By Banked Registers Purpose
User (USR) 10000 Normal program execution None extra Unprivileged application code
System (SYS) 11111 Software (privileged) Shares User regs OS tasks with User-mode register set
Supervisor (SVC) 10011 SWI instruction, reset R13_svc, R14_svc, SPSR_svc OS kernel entry via system calls
IRQ 10010 Normal interrupt (nIRQ pin) R13_irq, R14_irq, SPSR_irq Peripheral interrupt handlers
FIQ 10001 Fast interrupt (nFIQ pin) R8–R14_fiq, SPSR_fiq (7 banks!) High-speed DMA, real-time critical
Abort (ABT) 10111 Prefetch/data abort exception R13_abt, R14_abt, SPSR_abt Memory protection violations
Undefined (UND) 11011 Undefined instruction trap R13_und, R14_und, SPSR_und Coprocessor emulation, VFP soft-float

How Modes Optimize Performance

1
FIQ Mode — Ultra-fast Interrupt Response: FIQ banks R8–R14 (7 registers). Normal interrupt handlers must save/restore these registers. FIQ handler can use R8–R12 directly without pushing to stack. Result: ISR entry is 5–7 cycles faster — critical for 1µs-deadline handlers like DMA completion in audio/DSP.
2
Thumb State — Code Density Optimization: T bit in CPSR selects 16-bit Thumb instructions vs 32-bit ARM. Thumb code is ~65–70% of ARM code size — fits more code in limited Flash. Cortex-M uses Thumb-2 exclusively (mix of 16+32-bit) for optimal density + performance.
3
Efficient Context Switching: Each mode has own SP and LR. OS saves CPSR to SPSR automatically on exception entry. Return restores from SPSR. Context switch overhead: PUSH {R0–R12, LR} = 14 registers × 4 bytes = 56 bytes on stack. Cortex-M auto-saves R0–R3, R12, LR, PC, xPSR in hardware — reducing ISR overhead.

Multitasking Support

  • RTOS task switching: SVC instruction (SWI) enters Supervisor mode → OS kernel context switch → loads different task's SP (R13), restores its R0–R15
  • Preemption: IRQ fires → CPU saves PC+CPSR, loads IRQ_SP → ISR runs → MOVS PC, LR restores context
  • Stack separation: Each mode has its own SP → User stack overflow cannot corrupt OS stack
  • Cortex-M dual stack: MSP (Main Stack Pointer) for privileged/OS; PSP (Process Stack Pointer) for each RTOS task → clean separation

Security via Mode Separation

  • Privilege levels: User mode cannot write to CPSR (mode bits) — cannot escalate privileges without going through SVC (controlled OS entry point)
  • Memory Protection Unit (MPU): Cortex-M3/M4 MPU enforces read/write/execute permissions per memory region. User tasks cannot access kernel memory — isolation guaranteed
  • TrustZone (ARMv8): Secure World and Non-Secure World at hardware level. Secure Monitor Mode (SMC instruction) is the only gateway between worlds. Cryptographic keys in Secure World are inaccessible to normal OS
  • Abort mode: Memory access violations trap to Abort mode → OS can terminate faulting task cleanly without system crash
📝 Exam Tip: Key facts: FIQ has 7 banked registers (R8–R14) — unique advantage. CPSR holds mode, T-bit (ARM/Thumb), NZCV flags, I/F interrupt disable. Mode switch: CPSR copied to SPSR automatically. Cortex-M has 8 exception priorities (0–7, lower number = higher priority) instead of traditional modes.

3-bit R-2R Ladder Network: D2=1(MSB) D1=0 D0=1(LSB) │ │ │ 2R 2R 2R │ │ │ ┼───────R───────┼───────R───────┼───── Vout (to op-amp buffer) │ │ │ 2R 2R 2R │ │ │ GND GND GND Switch positions for 101: D2=1 → Switch at Vref (5V) D1=0 → Switch at GND D0=1 → Switch at Vref (5V)

Thevenin Analysis — Step by Step

  1. D0 node (LSB): Thevenin voltage = Vref×(2R∥2R)/(2R + 2R∥2R) = Vref/2. Thevenin resistance = 2R∥2R∥2R combination → R_th = R at each node junction

  3. D2 node (MSB): Contribution = Vref/2 (largest weight)
  4. Superposition: Vout = D2×(Vref/2) + D1×(Vref/4) + D0×(Vref/8)

D2=1, D1=0, D0=1 → Decimal value = 5

Vout = Vref × (D2 × 2² + D1 × 2¹ + D0 × 2⁰) / 2³
Vout = 5 × (1×4 + 0×2 + 1×1) / 8
Vout = 5 × 5 / 8
Vout = 3.125 V

Resolution: Vref/2³ = 5/8 = 0.625 V per step (LSB)

Embedded Networking Protocols define rules for data exchange between nodes in an embedded network — covering physical layer (voltage levels, connectors), data link layer (framing, error detection, arbitration), and application layer (message interpretation). They enable distributed embedded systems where multiple ECUs collaborate.

CAN Bus Architecture

CAN (Controller Area Network) developed by Bosch (1986) — a robust serial bus standard for connecting ECUs in automotive and industrial applications. Uses differential signaling for excellent noise immunity over long distances. Multi-master, broadcast architecture — no dedicated bus master.

CAN Frame Format

Standard CAN Frame (11-bit ID): ┌─────┬──────────────┬─────┬─────┬──────┬────────────────┬─────────────┬─────┬─────┐ │ SOF │ ID (11-bit) │ RTR │ IDE │ DLC │ Data (0-8B) │ CRC+Delim │ ACK │ EOF │ │ 1 │ 11 bits │ 1 │ 0 │ 4 b │ 0-64 bits │ 15+1 bit │ 2 │ 7 │ └─────┴──────────────┴─────┴─────┴──────┴────────────────┴─────────────┴─────┴─────┘ SOF (Start Of Frame): Dominant bit — synchronizes all nodes ID: 11-bit message identifier — determines priority (lower=higher priority) RTR: Remote Transmission Request (0=data frame, 1=remote frame) IDE: Identifier Extension (0=standard 11-bit, 1=extended 29-bit) DLC: Data Length Code (0–8, number of data bytes) CRC: 15-bit Cyclic Redundancy Check for error detection ACK: Any node receiving correctly pulls ACK dominant EOF: 7 recessive bits mark end of frame IFS: 3-bit Interframe Space before next frame

CAN Key Mechanisms

  • Non-destructive Arbitration (CSMA/CA): All nodes start transmitting simultaneously. Each bit is compared — dominant (0) wins over recessive (1). The node sending the lower ID wins. Losing nodes back off and retry. No data is lost — the winning frame completes correctly.
  • Bit Stuffing: After 5 consecutive identical bits, a complementary stuff bit is inserted automatically. Receiver removes stuff bits. Ensures sufficient transitions for clock synchronization.
  • Error Detection (5 methods): CRC-15 check | Bit monitoring | Bit stuffing rule | Frame check | ACK check.
  • Error Confinement: Nodes maintain error counters (TEC, REC). Persistent errors → node goes "error passive" → then "bus-off" (disconnects to protect bus).
  • Message Filtering: Each CAN controller has acceptance filter — only processes frames with matching IDs. Software receives only relevant messages.

Q11. What is UART? Write a program for 8051 to transfer the data "EXAM" serially at 9600 baud, 8-bit data, 1 stop bit. 10 Marks

Answer — UART & Serial Transmission of "EXAM"

UART (Universal Asynchronous Receiver Transmitter) is an asynchronous serial communication protocol that transmits data one bit at a time over a single wire (TXD) without a separate clock line. Synchronization is achieved by agreement on baud rate and frame format between sender and receiver.

UART Frame Format

UART Frame (8N1 — 8 data bits, No parity, 1 stop bit): ┌─────┬───┬───┬───┬───┬───┬───┬───┬───┬──────┐ │START│ D0│ D1│ D2│ D3│ D4│ D5│ D6│ D7│ STOP │ │ 0 │ │ │ │ │ │ │ │ │ 1 │ └─────┴───┴───┴───┴───┴───┴───┴───┴───┴──────┘ ↑ ↑ Falling edge signals start HIGH marks end (idles HIGH, START = LOW transition) Total bits per character = 1+8+1 = 10 bits At 9600 baud: time per bit = 1/9600 = 104.2 µs Total char time = 10 × 104.2 µs = 1042 µs ≈ 1.04 ms per character

8051 UART SFRs

SCON (Serial Control Register) — Address 0x98 (bit-addressable) Bit: [SM0][SM1][SM2][REN][TB8][RB8][TI][RI] 7 6 5 4 3 2 1 0 SM0+SM1: 00=Mode0, 01=Mode1(8-bit UART, baud by T1), 10=Mode2, 11=Mode3 REN: Receive Enable (1=enable serial receive) TI: Transmit Interrupt flag (set when TX complete) RI: Receive Interrupt flag (set when RX complete) SBUF (Serial Buffer) — Address 0x99 Writing SBUF starts transmission; Reading SBUF retrieves received byte For 9600 baud at 11.059 MHz: TH1 = 256 - (11059200 / (192 × 9600)) = 256 - 6 = 250 = 0xFD Timer 1 Mode 2 (auto-reload), PCON.SMOD=0

    TH1  = 0xFD;    // 9600 baud @ 11.059 MHz: 256-6=250=0xFD

    TR1  = 1;       // Start Timer 1 (baud rate generator)

void serial_send_char(char ch) {
    SBUF = ch;              // Load character into TX buffer
    while(TI == 0);         // Wait until transmission complete
    TI = 0;                 // Clear TI flag for next character
}

8051 Memory Address Space

8051 has 16-bit address bus → 64KB addressable space Program Memory (PSEN): 0x0000 – 0xFFFF (64KB) Data Memory (RD/WR): 0x0000 – 0xFFFF (64KB, separate space) With EA=1 (internal ROM): 0x0000–0x0FFF from internal (4KB) 0x1000–0xFFFF from external With EA=0: All 64KB from external program memory Port P2 (A8–A15): Upper 8 address bits Port P0 (AD0–AD7): Multiplexed Address (low)/Data bus ALE (Address Latch Enable): Pulses HIGH to latch address on P0 before data appears on P0

Address Decoder Using 74LS138 (3-to-8 Decoder)

The 74LS138 is a 3-to-8 line decoder: 3 address inputs (A, B, C) select one of 8 active-LOW outputs. Connected to the upper address lines (A13, A14, A15) of the 8051, it generates chip select signals for each 8KB memory block.
74LS138 Address Decoder — 8051 Memory Mapping: A15 → C (MSB) A14 → B → Y0 → CS of RAM at 0x0000–0x1FFF (8KB) A13 → A (LSB) → Y1 → CS of ROM at 0x2000–0x3FFF (8KB) → Y2 → CS of EEPROM at 0x4000–0x5FFF → Y3 → CS of I/O at 0x6000–0x7FFF G1=VCC, G2A=G2B=GND → Y4–Y7: Available for more devices When A15,A14,A13 = 0,0,0 → Y0 active (LOW) → RAM enabled When A15,A14,A13 = 0,0,1 → Y1 active → ROM enabled 8051 Connection: P2.5 (A13) → A input of 74LS138 P2.6 (A14) → B input P2.7 (A15) → C input GND → /G2A, /G2B (enable pins active LOW) VCC → G1 (enable pin active HIGH) Each output drives the /CE (Chip Enable) of one memory IC
